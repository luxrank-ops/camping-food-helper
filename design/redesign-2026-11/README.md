## 1. 왜 이렇게 바꾸는가

현행 앱은 이미 좋은 뼈대를 갖고 있습니다. 다크 테마 + 크림 카드 + 코랄 CTA, 44px 터치, 라이트 테마 토글까지 갖춰져 있죠. 이번 시안은 **뼈대를 바꾸지 않고** 아래 3가지만 손봅니다.

### ① 바탕은 더 어둡게, 정보는 더 밝게
- `--bg #0E2820` → `#06170F` / `#0A2018`
- 카드(`#13382A`)가 배경에서 **떠 보이게** 되어, 사진과 CTA가 먼저 눈에 들어옵니다.
- 야간 캠핑(불멍)에서 눈부심이 줄고, 낮에는 라이트(모닝) 테마로 전환합니다.

### ② 사진이 주인공
- 기존: 텍스트 카드 + 작은 썸네일 중심 → **신규: 카드 상단 16:9 사진 + 하단 스크림 위 정보**
- 날씨 카드에도 캠핑지 사진을 깔아 "지금 어디서, 어떤 날씨인지" 3초 안에 읽힙니다.
- 사진 위 텍스트는 **항상 그라데이션 스크림**(`rgba(6,23,15,0)` → `rgba(6,23,15,.97)`) 위에 올립니다.

### ③ 상태를 두 번 말한다
- 완료·진행·오프라인을 **색 + 아이콘 + 문장**으로 함께 표시합니다.
  - 준비물: 체크박스 채움(코랄) + 취소선 + 항목 수 감소
  - 조리 단계: 완료(녹색 체크) / 진행(코랄 좌측 바 + 타이머) / 대기(회색 동그라미)
  - 오프라인: `기기에 저장됨` 배지
- 밝은 야외, 장갑 낀 손, 화면 반사 상황에서도 구분됩니다.

## 2. 컬러 토큰 (현행 → 신규)

| 역할 | 현행 | 신규 | 비고 |
|---|---|---|---|
| 배경(최심) | `#0E2820` | `#06170F` | 야간 불멍 기준 |
| 배경(본문) | `#0E2820` | `#0A2018` | |
| 카드 표면 | `#17382D` | `#13382A` | 경계는 `rgba(245,239,226,.10)` |
| 기본 텍스트 | `#F4F1E3` | `#F5EFE2` | 크림 톤 유지 |
| 보조 텍스트 | `#A8C1B5` | `#9FB6A6` | 대비 4.5:1 이상 |
| 캡션 | — | `#6F887A` | 10px 이하 전용 |
| CTA | `#F4735A` | `#FF7A59` → `#F0502E` | 그라데이션 135° |
| 강조 배지 | `#EEF3B2` | `#E6ECAF` | 모스빛 크림 |
| 비/물 | — | `#8FC3D9` | 날씨 배지 |
| 완료 | `#8ED9B2` | `#6FD3A0` | |
| 라이트 배경 | `#F3F0E4` | `#F6F2E7` | 모닝 |
| 라이트 CTA | `#D9462B` | `#E04E2A` | |

**규칙**
- 코랄은 **화면당 1~2곳**(주요 CTA + 선택 상태)만. 나머지는 중립 면·보더로.
- 사진 위 흰 텍스트는 반드시 스크림을 동반. 스크림 없이 흰 글씨 금지.
- 라이트 모드에서 코랄은 채도를 한 단계 낮춰(#E04E2A) 크림 배경과 부딪히지 않게.

## 3. 타이포그래피

| 역할 | 폰트 | 크기 / 굵기 | 자간 |
|---|---|---|---|
| Display (화면 제목) | Do Hyeon | 29px / 400 | -0.4px |
| Title (섹션·카드 제목) | Do Hyeon | 23~24px / 400 | -0.3px |
| Heading | Gothic A1 | 14px / 900 | -0.3px |
| Body | Gothic A1 | 12.5px / 500 | -0.15px |
| Caption | Gothic A1 | 10px / 700 | -0.1px |
| Label(영문) | Gothic A1 | 9px / 900 | +0.1em |
| 숫자(온도·타이머) | Do Hyeon | 15~33px / 400 | `tabular-nums` |

**규칙**
- 한 화면에 Display는 1개. 두 줄 초과 금지.
- 숫자는 Do Hyeon + `font-variant-numeric: tabular-nums` (타이머 흔들림 방지).
- 본문 최소 10px, 중요 정보는 11px 이상.
- 영문 라벨은 대문자 + 자간 0.1em → 캠프 장비 감성.

## 5. 화면별 변경 요약

### 01 홈 · 오늘의 추천
- **변경**: 상단에 브랜드 + 테마 토글 / 날씨 사진 카드 / 큰 추천 카드(사진) / 다른 후보 가로 스크롤 / 준비물 진행 카드
- **이유**: 첫 화면에서 "오늘 뭐 먹지"를 3초 안에 결정. 기존 '빠른 길잡이 4버튼'은 하단 탭·전체메뉴와 중복이라 **추천에 집중**하도록 정리.
- **주의**: 추천 카드 CTA는 1개만(`준비물 만들기`). `다시 고르기`는 텍스트 링크.

### 02 준비물 · 장보기
- **변경**: 3분류(집에서 손질 / 챙기기 / 현장 구입) 태그 + 진행률 도넛 + 태그별 남은 개수 요약
- **이유**: "집에서 2, 챙기기 4, 현장 2"를 한 줄로 보여 주면 출발 전 점검이 빨라짐.
- **주의**: 완료 항목은 취소선 + 흐린 색. 태그 색은 3종 고정(파랑/크림/코랄).

### 03 레시피 · 조리 모드
- **변경**: 상단 사진 몰입(286px) / 조리·인원·난이도 3분할 / 단계 리스트(완료·진행·대기) / 진행 단계에 타이머 버튼 / 하단 고정 CTA
- **이유**: 현장에서 한 손으로 "지금 몇 단계인지" 확인. 타이머는 단계 안에 붙여 스크롤 없이 조작.
- **주의**: 진행 단계는 좌측 3px 코랄 바 + 배경 틴트로 이중 표시.

### 04 캠핑지 탐색
- **변경**: 검색바 + 거리순/노지/오토/반려견 칩 + 지도 프리뷰(핀) + 캠핑지 카드(점수·날씨 배지·태그) + 직접 등록 진입
- **이유**: 리스트만으로는 "어디가 가까운지" 감이 안 옴. 지도 프리뷰 1장으로 공간 감각 제공.
- **주의**: 공공데이터에 없는 정보(요금·예약·반려견)는 지어내지 않고 `확인 필요` 표기 원칙 유지.

### 05 주간 식단표
- **변경**: 2박 3일 히어로(끼니·재료·예상 장보기) / 날짜 탭 / DAY 카드(끼니별 사진·시간·장비) / 빈 끼니는 `+ 메뉴 고르기` / 하단 `6끼니 한 번에 취합`
- **이유**: 장박은 "끼니 6개를 한 번에 계획"하는 것이 핵심. 예산이 보이면 과구매가 줄어듦.
- **주의**: 빈 상태도 빈 카드가 아니라 다음 행동(추천)을 붙임.

### 06 전체 메뉴 시트
- **변경**: 2열 카드 그리드(아이콘 + 이름 + 한 줄 설명 + 현재 표시) / 계정·요금제 / 약관 링크
- **이유**: 기존 7~8개 메뉴를 리스트가 아닌 카드로 → 한눈에 스캔, 터치 영역 확대.
- **주의**: 시트는 690px 높이 고정, 배경 디밍 + 블러 2px. ESC/배경 탭으로 닫힘.

### 07 라이트(MORNING) 테마
- **변경**: 크림 배경 + 흰 카드 + 남색-그린 텍스트. 사진 위 텍스트는 다크 스크림 유지.
- **이유**: 낮 야외(햇빛·반사)에서 다크 테마는 화면이 검게 보임. 라이트 모드를 "야외 가시성 모드"로 명확히 포지셔닝.
- **주의**: 라이트에서 코랄(#E04E2A)은 흰 배경 대비 4.5:1 이상. 사진 위 흰 텍스트는 스크림 필수.

## 6. 적용 순서 (권장 · 리스크 낮은 순)

| 단계 | 작업 | 파일 | 예상 |
|---|---|---|---|
| **1** | `:root` 토큰 값 교체 (색·반경·그림자) | `index.html` `<style>` 상단 | 30분 |
| **2** | 카드 3종 시각 규칙 적용(추천·준비물·캠핑지) | `index.html` CSS + `recommendationCard()` 등 | 3~4시간 |
| **3** | 상태 표현 통일(체크박스·진행률·오프라인 배지) | `index.html` CSS | 2시간 |
| **4** | 라이트(모닝) 모드 점검 — 대비·스크림·터치 | `index.html` `data-theme="light"` | 2시간 |
| **5** | (선택) 첫 화면 구조 개편 — 빠른 길잡이 → 추천 중심 | `recView()` | 4시간+ |

> 1단계만 해도 화면 인상의 절반이 바뀝니다. **토큰 → 카드 → 상태 → 라이트** 순서로 쪼개서 배포하면 회귀 위험이 낮습니다.

### 1단계 예시 (그대로 붙여넣을 수 있는 값)

```css
:root{
  --bg:#0A2018; --surface:#13382A; --fg:#F5EFE2; --muted:#9FB6A6;
  --line:rgba(245,239,226,.10); --chip:rgba(255,255,255,.05);
  --brand:#FF7A59; --brand-fg:#2A0E06; --cta:#FF7A59; --cta-fg:#2A0E06;
  --pop:#E6ECAF; --pop-fg:#1B2610; --ok:#6FD3A0;
  --shadow:0 20px 40px -28px rgba(0,0,0,.9);
  --shadow-up:0 24px 44px -18px rgba(0,0,0,.95);
}
```

> 주의: 현행 코드는 `--bg`를 `body` 배경으로도 쓰기 때문에, 최심 배경(`#06170F`)은 **별도 토큰(`--bg-deep`)** 으로 추가하고 `body`는 `--bg`를 유지하는 편이 안전합니다.

## 7. 가이드 · 체크리스트

- [ ] 한 화면에 Display(Do Hyeon) 1개, 제목 2줄 이내
- [ ] 숫자(온도·타이머·개수) `tabular-nums`
- [ ] 사진 위 텍스트는 항상 스크림 동반
- [ ] 본문 최소 10px, 대비 4.5:1 이상
- [ ] 터치 영역 44×44 이상, 주요 CTA 52px 이상
- [ ] 하단 탭 5개 유지, 현재 화면 `aria-current="page"`
- [ ] 빈 화면 금지 — 안내 문장 + 다음 행동 1개
- [ ] 이모지 최소화, 아이콘은 1.8px 인라인 SVG
- [ ] `prefers-reduced-motion` 존중(전환·애니메이션)
- [ ] 라이트 모드에서 사진 위 텍스트 대비 재확인

## 8. 열린 질문 (결정 필요)

1. **첫 화면 구조** — 현행 `빠른 길잡이 4버튼`을 유지할까요, 아니면 시안처럼 **추천 카드 중심**으로 갈까요?
   (추천 중심이면 첫 화면 정보량은 줄고 결정 속도는 빨라집니다.)
2. **사진 소스** — 시안은 생성 이미지를 썼습니다. 실제 서비스에서는 요리 사진(Gemini 생성 이미지 API)과 캠핑지 사진(사용자 업로드/공공데이터) 중 어디까지 자동화할까요?
3. **라이트 모드 기본값** — 시스템 설정을 따를지, **야외 시간대(일출~일몰) 자동 전환**을 넣을지?
4. **점수·평점 노출** — 캠핑지 카드의 `4.9점`은 현재 데이터에 없는 예시값입니다. 실제 데이터가 없다면 제거하거나 `추천` 배지로 대체해야 합니다.
